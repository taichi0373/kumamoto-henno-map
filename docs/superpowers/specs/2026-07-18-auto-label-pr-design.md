# 設計書: PR自動ラベル付与ワークフロー

**作成日:** 2026-07-18
**対象ブランチ:** `ci/auto-label-pr`

---

## 概要

プルリクエスト作成時に、ブランチ名と変更ファイルパスを判定して適切なラベルを自動付与する。

---

## 対象ファイル

- `.github/workflows/auto-label-pr.yml`（既存ファイルを全面改修）

---

## トリガー

| 項目 | 設定値 |
|------|--------|
| イベント | `pull_request_target` |
| タイプ | `opened` |
| 備考 | フォークPRでも書き込み権限を持てる安全なイベント。コードのチェックアウトは行わない。 |

---

## ジョブ構成

1ジョブ・2ステップ構成。権限は `pull-requests: write` のみ。

```
Job: label
  Step 1: ブランチ名でタイプ・リリースノートラベルを付与
  Step 2: 変更ファイルでエリアラベルを付与
```

---

## Step 1: ブランチ名判定ロジック

`github.head_ref`（PRのソースブランチ名）を `case` 文で判定し、ラベルを付与する。

| ブランチパターン | 付与ラベル |
|----------------|-----------|
| `feature/*` | 機能追加、リリースノート対象 |
| `bugfix/*` / `hotfix/*` | バグ、リリースノート対象 |
| `docs/*` | ドキュメント、リリースノート除外 |
| `ci/*` | CI/CD、リリースノート除外 |
| `refactor/*` / `test/*` | リリースノート除外のみ |
| その他 | リリースノート対象のみ |

---

## Step 2: 変更ファイル判定ロジック

`gh pr diff --name-only` で変更ファイル一覧を取得し、パスを grep でチェックしてエリアラベルを付与する。

| ファイルパスパターン | 付与ラベル |
|--------------------|-----------|
| `apps/front/` を含む | フロントエンド |
| `apps/back/` を含む | バックエンド |
| `.github/` を含む | CI/CD |

※ CI/CD ラベルはStep 1でも付与されうるが、`gh pr edit --add-label` は冪等に動作するため重複付与は問題なし。

---

## 既存ワークフローとの関係

| ワークフロー | 変更 |
|------------|------|
| `auto-label-pr.yml` | 全面改修（本設計の対象） |
| `dependabot.yml` | 変更なし（Dependabot PRは独自ラベルを持つ） |
| `release.yml` | 変更なし（「リリースノート除外」ラベルで除外判定） |

---

## 非機能要件

- 外部 GitHub Actions への依存なし
- `pull_request_target` を使用するが、コードのチェックアウト・実行は行わない
- 全処理は `gh` CLI のみで完結
